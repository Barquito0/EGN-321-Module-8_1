# Silent Handoff Protocol — author and assigned operator

## Before the classmate arrives

The author ensures the repository is available, but does **not** pre-complete the task sheet for the partner. Share only this repository and the operating guide. Use a machine where the partner can install Python packages and Git without handing over passwords. Agree on whether screen recording or screenshots are allowed.

## Rules for the author

Observe and take notes. **Stay silent** throughout the test. Do not provide a command, point at a button, fix the operator's terminal, interpret an error, or tell the operator where to click. When the operator asks for help, note the request and whether they found the answer in the documentation. Never fill a success cell by assumption.

## Rules for the operator

Use only the repository, README, included data, and application. Carry out [`OPERATOR_TASK_SHEET.md`](OPERATOR_TASK_SHEET.md) from top to bottom. Announce a step as completed/stuck so the author can time and record it. If blocked, write the exact error message and the section searched. Do not ask the author to rescue the test.

## Evidence collection

- Record date, approximate local time and the partner's permission to record screenshots (no personal identity required).
- Record each attempt as `Yes`, `No`, or `Partial` in the observation table.
- Save screenshots of a working dashboard, one normal updated value, a paused source or other documented problem, a successful recovery if achieved, and the log location. Screenshot filenames should reflect **what was actually observed**.
- Remove/redact local usernames, home directory details, credentials and private data from shared screenshots.
- Do not backdate or simulate a partner's actions. If a task is skipped or unachievable, say so.

## After the classmate leaves

1. Finalize [`HANDOFF_OBSERVATION_TEMPLATE.md`](HANDOFF_OBSERVATION_TEMPLATE.md) with factual outcomes.
2. List problems in [`PROBLEMS_FOUND_TEMPLATE.md`](PROBLEMS_FOUND_TEMPLATE.md).
3. Implement **at least two meaningful changes motivated by observed struggles**. Include before/change/after and verification evidence.
4. Have someone independently retry the affected steps if practical.
5. Complete [`REFLECTION_TEMPLATE.md`](REFLECTION_TEMPLATE.md) in your own words.
6. Commit the final observations, screenshots, changes and reflection. Do not label empty templates as completed evidence.
